Каждое из 77 отношений показано ровно на одной диаграмме отношений, каждый класс — на диаграмме пакетов и на одной детальной диаграмме (контроль целостности по [5], п. 4.3.3). Отношения: ассоциаций 7, агрегаций 4, композиций 7, зависимостей 49 («call» — 20, «use» — 19, «instantiate» — 8, «create» — 2), обобщений 7, реализаций 3; количественная характеристика каждой диаграммы — в её документировании. Членов классов: 117 атрибутов (без значений перечислений) и 152 операции.

## Решения
- Классы выделены по автоматам ЛР3: простое состояние, которое выполняет система, — граничный класс (показ окна) или управляющий класс и его операция (обработка); близкие состояния одного прецедента сведены в один класс ([5], с. 39). Состояния, которые выполняет человек, классов не порождают — их исполнитель «условный» класс-актор ([5], с. 41). Таблица соответствия — в конце [документирования](../02_Документирование/Документирование_диаграмм.md).
- Сущности — по таблицам БД (`02_Архитектура_системы/03`, `/09`); поля JSON (параметры генерации и шума) — отдельные классы, связанные композицией. Состояния жизненных циклов (учётная запись, подписка, задача генерации) — значения перечислений; у перечислений отсек операций скрыт.
- Имена классов и членов — на русском языке, типы — в нотации Python (str, int, Decimal, datetime, UUID, list[…], dict). Атрибуты закрыты (-), операции для других классов открыты (+), вспомогательные — закрыты (-), члены для потомков — защищены (#).
- У каждого атрибута и операции в Documentation — назначение и обоснование типа (типы параметров и результата), как требует [5], п. 4.3.2.
- Ассоциации — по внешним ключам, стрелка от зависимого класса к независимому, имя — глагольная фраза; композиция — когда часть удаляется вместе с целым (версии тарифа, этапы и карты материала, параметры), агрегация — когда часть живёт отдельно (провайдер подсказок, платёжная система, версия модели, учётная запись сотрудника). Выбор обоснован в документировании каждой стрелки.
- Зависимости: «call» — вызов операций, «use» — чтение или изменение данных, «instantiate» — создание объекта класса-сущности, «create» — открытие окна другим окном.
- Внешние системы ЛР1 (почтовый сервис, платёжная система, языковая модель) — граничные классы; платёжная система и провайдер подсказок — интерфейсы с реализациями, чтобы менять поставщика без изменения контроллеров.
- Наследники (воркеры, панели персонала, реализации интерфейса) нарисованы деревом с общим участком к родителю (допустимая в UML форма «shared target style»).
- StarUML 6: `UMLClass` (стереотипы entity / boundary / control / enumeration), `UMLInterface`, `UMLAssociation` (aggregation на конце целого), `UMLDependency` со стереотипом, `UMLGeneralization`, `UMLInterfaceRealization`; StarUML 5.0: `UMLAssociationEnd` (akAggregate / akComposite), `UMLRealization`.
