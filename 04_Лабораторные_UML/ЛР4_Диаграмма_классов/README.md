# ЛР4. Диаграмма классов

Источники: [5] гл. 4 (с. 35–46); [6] вторая гл. 6, 7, 9–12 (интерфейс StarUML); DDD — Эванс, Вернон, Фаулер; правила чистого кода — скилл ub-mode (unclebob) и «Чистый код» Р. Мартина.
Предметная область — та же система генерации бесшовных PBR-материалов; модель продолжает проект ЛР1–ЛР3.

## Задание и требования методички ([5], гл. 4)
- [x] Классы выделены по диаграммам поведения: каждому простому состоянию автоматов ЛР3, которое выполняет система, — свой класс или операция класса; состояния, которые выполняет человек, — «условный» класс-актор ([5], с. 39–41).
- [x] Пакеты классов-сущностей («entity»), граничных («boundary») и управляющих («control») классов.
- [x] Три вида диаграмм ([5], п. 4.3.2): диаграмма пакетов с вложенными классами; диаграммы детального представления (все атрибуты и операции, видимость `+ - #`, типы атрибутов, параметров и результатов); диаграммы отношений (классы — именами).
- [x] У каждого члена класса в Documentation — назначение и обоснование типа.
- [x] Ассоциации — «отношения по данным»: проявляются атрибутами-идентификаторами, стрелка от зависимого класса к независимому, имя — глагольная фраза; выбор агрегации или композиции обоснован у каждой стрелки.
- [x] Зависимости со стереотипами «call», «use», «instantiate», «create»; обобщения и реализации интерфейсов.
- [x] Документирование диаграммы пакетов — число пакетов и классов в каждом ([5], п. 4.3.3); все классы диаграммы пакетов есть на детальных диаграммах.
- [x] Документирование всех диаграмм и элементов (Documentation) и перенос в отчёт.

## DDD и чистый код (30.10.2026)
Модель проверена по приёмам предметно-ориентированного проектирования и правилам ub-mode; 13 находок исправлены, сознательные отступления описаны — [01_Модель/Оценка_DDD_и_чистого_кода.md](01_Модель/Оценка_DDD_и_чистого_кода.md). Коротко:
- корни агрегатов с операциями-переходами жизненных циклов вместо «СменитьСтатус()»; части агрегата — только через корень;
- неизменяемые объекты-значения `{readOnly}`: Деньги, Период, ПраваТарифа, ПараметрыГенерации и др.; перечисления вместо строк;
- агрегаты связаны по идентификаторам; смена тарифа между контекстами — событие «ТарифПользователяИзменён»;
- запросы отделены от команд, без флаговых аргументов и кодов возврата; контроллеры сотрудников разделены по разделам (SRP);
- 5 ограниченных контекстов и [глоссарий](01_Модель/Глоссарий.md).
