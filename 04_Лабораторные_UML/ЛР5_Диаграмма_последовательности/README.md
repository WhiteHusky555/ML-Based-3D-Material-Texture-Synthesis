# ЛР5. Диаграмма последовательности

Источники: [5] гл. 5 (с. 47–52); [6] гл. 8 (интерфейс StarUML).
Предметная область — та же система генерации бесшовных PBR-материалов; модель продолжает проект ЛР1–ЛР4.

## Задание и требования методички ([5], гл. 5)
- [x] Диаграммы построены по классам ЛР4, выделенным из деятельностей ЛР2 и автоматов ЛР3 (типовая схема, рис. 5.1); реализован каждый прецедент основной диаграммы ЛР1 (UC1–UC11) и декомпозиция «Обработка задачи генерации».
- [x] Требование преподавателя: на одной диаграмме не больше 3–4 линий жизни. Части сценариев вынесены в отдельные взаимодействия и вызываются фрагментом ref; генератор проверяет предел.
- [x] Надписи над сплошными стрелками — операции классов, в линию жизни которых входит стрелка; все они есть на диаграмме классов (проверяет генератор).
- [x] Ветвления, выполнение по условию и циклы — комбинированные фрагменты alt, opt, loop; у opt один операнд; условие loop — условие выполнения тела.
- [x] Объекты, создаваемые во время сценария, — со смещением вниз на уровень сообщения «create».
- [x] Документирование всех диаграмм и элементов (Documentation) и перенос в отчёт.

## Решения (02.11.2026)
- Линии жизни — объекты классов ЛР4 и акторы ЛР1; сервис архитектуры, где работает объект, — в Documentation линии жизни. Микросервисы, nginx и BFF как компоненты — в ЛР7–ЛР8.
- Вход через BFF (вариант C, `02_Архитектура_системы/17`): токены в сеансе на сервере (Redis), браузеру — cookie сеанса.
- Очереди — RabbitMQ (`02_Архитектура_системы/21`): задачи воркерам и события этапов — асинхронные сообщения.
