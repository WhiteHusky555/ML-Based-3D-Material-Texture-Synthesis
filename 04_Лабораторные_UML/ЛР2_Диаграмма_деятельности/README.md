# ЛР2. Диаграмма деятельности

Источники: [5] гл. 2 (с. 20–29); [7] гл. 2; [6] первая гл. 6 (интерфейс StarUML).
Предметная область: облачная система генерации бесшовных PBR-материалов (ВКР) — та же модель, что в ЛР1.

## Задание (по [5], п. 2.4)
1. Построить диаграммы деятельности для **каждого варианта использования основной диаграммы** прецедентов. Подпись: «Алгоритм реализации варианта использования <НАЗВАНИЕ ПРЕЦЕДЕНТА>».
2. Построить диаграммы деятельности, реализующие **ссылки на деятельности** (узлы SubactivityState) из диаграмм п. 1.
3. Документировать все диаграммы и все их элементы в секции Documentation.
4. Поместить все документирования всех диаграмм и их элементов в отчёт.

## Требования из методички (что проверено)
### Нотация ([5], п. 2.1–2.3)
- [x] Действие (ActionState) и ссылка на деятельность (SubactivityState, значок-«грабли») — скруглённые прямоугольники; ссылка именуется «имяСсылки:ИмяДеятельности».
- [x] Деятельность = диаграмма + её элементы; деятельности размещены в **Logical View**; имена диаграмм — латиницей с префиксом `D_` (рекомендация [5], с. 23).
- [x] Надписи над стрелками: триггерное событие (без скобок), сторожевое условие `[в скобках]`, действие на переходе не используется (в диаграммах деятельности практически не применяется).
- [x] Переход по завершению деятельности — **без надписей**; бесконечная деятельность (ожидание пользователя) завершается только по триггерным событиям.
- [x] Узел решения: над исходящими стрелками — условия, на одной — `[else]`; **никаких «Да/Нет»** (рис. 2.2 [5]).
- [x] Decision — и ветвление, и **слияние**: у состояния действия один вход, несколько входящих стрелок сводятся узлом слияния.
- [x] Разделы активности — плавательные дорожки: актор (логические действия человека, не «нажатия клавиш»), «Система» (серверная и клиентская части вместе, как рис. 2.3 [5]), внешние системы.
- [x] Начальное состояние одно, конечных может быть несколько.
- [x] Окно, в котором пользователь вводит данные или делает выбор, — **параллельные потоки** (рис. 2.3 [5]): узел разветвления (Fork) запускает отображение окна системой и действие пользователя, узел синхронизации (Join) продолжает алгоритм после их завершения; отображение окна завершается триггерным событием.
### Документирование ([5], п. 2.5)
- [x] Пояснение узла устраняет неполноту и неоднозначность названия, близко к программной реализации.
- [x] Ссылка, смысла которой не хватает текстом, имеет собственную диаграмму; для простых — обоснование «семантически проста…» с описанием алгоритма.
- [x] Пояснение стрелки — обоснование набора надписей (Triggers, Guard Condition, Effects) по примерным схемам [5].
- [x] Количественная характеристика каждой диаграммы.
### Отчёт
- [x] Титул по Приложению А [5]; тема, задание, рисунки, документирование; без теории.
