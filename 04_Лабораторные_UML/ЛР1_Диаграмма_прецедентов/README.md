# ЛР1. Диаграмма вариантов использования (прецедентов)

Источники: [5] гл. 1 (с. 7–19); [6] гл. 4, 5; [7] — оформление спецификаций и сценариев.
Предметная область: облачная система генерации бесшовных PBR-материалов (ВКР), с пользователями и тарифами.

## Задание (по [5], п. 1.4)
1. Построить диаграмму вариантов использования первого уровня — **основную**. Подпись: «Варианты использования проектируемой системы».
2. Построить диаграммы **декомпозиции** вариантов использования основной диаграммы. Подпись: «Декомпозиция варианта использования <НАЗВАНИЕ ПРЕЦЕДЕНТА>».
3. Документировать все диаграммы и все их элементы в секции Documentation.
4. Составить текстовые описания **сценариев использования системы каждым из акторов** (косвенно требует описаний потоков всех прецедентов всех диаграмм).
5. Прикрепить текстовые документы редактором вложений (вкладка Attachment) к соответствующим акторам — в StarUML 6 вкладки нет, тексты сценариев приложены к отчёту.
6. Поместить документирование и описания алгоритмов реализации в отчёт.

## Чек-лист требований
### Модель
- [x] На основной диаграмме 3–9 относительно независимых прецедентов, **без** include/extend между ними.
- [x] Названия прецедентов — **названия процессов** (не данных, не событий, не условий).
- [x] Между прецедентами нет ассоциаций; между акторами — только генерализация; актор–прецедент — только ассоциации.
- [x] Ассоциация направленная, если актор пассивен (запускает, задаёт данные, получает результат); ненаправленная — если участвует в диалоге.
- [x] Каждая декомпозиционная диаграмма содержит декомпозируемый прецедент в центре.
- [x] У extend — условие в свойстве Condition и пояснение «(точка расширения) [условие]» рядом со стрелкой.
- [x] Работники системы (Администратор, Аналитик, Владелец) — классы со стереотипом worker в виде иконки.
- [x] Информационные связи между независимыми прецедентами — заметками (Note + NoteLink), как на рис. 1.3 [5].
### Документирование ([7], п. 1.1.2)
- [x] Количественная характеристика каждой диаграммы (акторов, прецедентов, дуг).
- [x] Характеристика акторов.
- [x] Характеристика прецедентов: название и краткое изложение функциональности.
- [x] Характеристика отношений: каждое отношение обосновано по шаблонам из [5] п. 1.5.
- [x] Документирование самих диаграмм (Documentation без выделения).
### Сценарии и потоки
- [x] Сценарий для каждого актора (таблица как табл. 2 [5]).
- [x] Потоки для **каждого базисного** прецедента основной диаграммы (таблицы как табл. 3–4 [5]): название, действующие лица, краткое описание, пред- и постусловия, основной поток, альтернативные потоки (A), потоки ошибок (E), подпотоки (S), приоритет, частота.
- [x] Ссылки в основном потоке: `k. Am [c]`, `k. Sm [c]`, `k. Sm`, `(Em)`.
### Отчёт
- [x] Титул по Приложению А [5].
- [x] Тема, задание, рисунки диаграмм, тексты документирования, описания потоков.
- [x] Без теории; ориентир до 30 страниц.
