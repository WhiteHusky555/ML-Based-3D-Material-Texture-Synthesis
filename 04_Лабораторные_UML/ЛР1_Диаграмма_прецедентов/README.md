# ЛР1. Диаграмма вариантов использования (прецедентов)

Источники: [5] гл. 1 (с. 7–19); [6] гл. 4, 5; [7] — оформление спецификаций и сценариев.
Предметная область: облачная система генерации бесшовных PBR-материалов (ВКР), с пользователями и тарифами.

## Задание (по [5], п. 1.4)
1. Построить диаграмму вариантов использования первого уровня — **основную**. Подпись: «Варианты использования проектируемой системы».
2. Построить диаграммы **декомпозиции** вариантов использования основной диаграммы. Подпись: «Декомпозиция варианта использования <НАЗВАНИЕ ПРЕЦЕДЕНТА>».
3. Документировать все диаграммы и все их элементы в секции Documentation.
4. Составить текстовые описания **сценариев использования системы каждым из акторов** (косвенно требует описаний потоков всех прецедентов всех диаграмм).
5. Прикрепить текстовые документы редактором вложений (вкладка Attachment) к соответствующим акторам.
6. Поместить документирование и описания алгоритмов реализации в отчёт.

## Чек-лист требований
### Модель
- [ ] На основной диаграмме 3–9 относительно независимых прецедентов, **без** include/extend между ними.
- [ ] Названия прецедентов — **названия процессов** (не данных, не событий, не условий).
- [ ] Между прецедентами нет ассоциаций; между акторами — только генерализация; актор–прецедент — только ассоциации.
- [ ] Ассоциация направленная, если актор пассивен (запускает, задаёт данные, получает результат); ненаправленная — если участвует в диалоге.
- [ ] Каждая декомпозиционная диаграмма содержит декомпозируемый прецедент в центре.
- [ ] У extend — условие в свойстве Condition и пояснение «(точка расширения) [условие]» рядом со стрелкой.
- [ ] Работники системы (Администратор, Аналитик, Владелец) — классы со стереотипом worker в виде иконки.
- [ ] Информационные связи между независимыми прецедентами — заметками (Note + NoteLink), как на рис. 1.3 [5].
### Документирование ([7], п. 1.1.2)
- [ ] Количественная характеристика каждой диаграммы (акторов, прецедентов, дуг).
- [ ] Характеристика акторов.
- [ ] Характеристика прецедентов: название и краткое изложение функциональности.
- [ ] Характеристика отношений: каждое отношение обосновано по шаблонам из [5] п. 1.5.
- [ ] Документирование самих диаграмм (Documentation без выделения).
### Сценарии и потоки
- [ ] Сценарий для каждого актора (таблица как табл. 2 [5]).
- [ ] Потоки для **каждого базисного** прецедента основной диаграммы (таблицы как табл. 3–4 [5]): название, действующие лица, краткое описание, пред- и постусловия, основной поток, альтернативные потоки (A), потоки ошибок (E), подпотоки (S), приоритет, частота.
- [ ] Ссылки в основном потоке: `k. Am [c]`, `k. Sm [c]`, `k. Sm`, `(Em)`.
### Отчёт
- [ ] Титул по Приложению А [5].
- [ ] Тема, задание, рисунки диаграмм, тексты документирования, описания потоков.
- [ ] Без теории; ориентир до 30 страниц.

## Как пересобрать
1. `01_Модель`: `python -I модель_ЛР1.py` — модель StarUML и документирование.
2. `_инструменты`: `python -I mdj_render.py --check ../ЛР1_Диаграмма_прецедентов/01_Модель/ЛР1_Прецеденты.mdj` — проверка, что ничего не перекрывается; затем `python -I mdj_render.py ../ЛР1_Диаграмма_прецедентов/01_Модель/ЛР1_Прецеденты.mdj ../ЛР1_Диаграмма_прецедентов/04_Изображения D1_Основная D2_Регистрация_и_вход D3_Генерация_материала D4_Экспорт_материала D5_Работа_с_историей D6_Управление_подпиской D7_Просмотр_в_3D D8_Администрирование_системы D9_Анализ_показателей D10_Тарифы_и_персонал --png` — SVG в `04_Изображения/SVG`, PNG (через LibreOffice) в `04_Изображения/PNG`.
3. `03_Сценарии`: `python -I потоки_ЛР1.py` — Markdown-таблицы.
4. `05_Отчёт`: `python -I собрать_отчёт_ЛР1.py` — отчёт docx (нужен Node.js и пакет `docx` в `_инструменты`).
