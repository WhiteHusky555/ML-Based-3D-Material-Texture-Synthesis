# UC1. Описание прецедента «Регистрация и вход в систему»

| Поле | Содержание |
|---|---|
| Название | S1. Реализация прецедента «Регистрация и вход в систему» |
| Действующие лица | Пользователь, Почтовый сервис |
| Краткое описание | Пользователь создаёт учётную запись, входит по e-mail и паролю или восстанавливает пароль. Окно предоставляет возможность досрочного завершения общения с системой. |
| Предусловия | Пользователь открыл веб-приложение; вход не выполнен. |
| Постусловия | Пользователь вошёл в систему и получил токены доступа либо завершил работу. |
| Основной поток | 1. Система отображает окно входа: поля e-mail и пароль, кнопка «Войти», ссылки «Зарегистрироваться» и «Забыли пароль?», кнопка закрытия.<br>2. Пользователь выбирает действие (точка расширения «Выбор действия»).<br>3. S1. [Выбрана регистрация] // Регистрация учётной записи<br>4. S2. [Выбран вход] // Вход по e-mail и паролю<br>5. S3. [Нажата «Забыли пароль?»] // Восстановление пароля<br>6. Выполнение прецедента завершается. |
| Альтернативные потоки | Альтернативных потоков нет. |
| Потоки ошибок | E1. [Нажата кнопка закрытия окна]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Выполнение прецедента завершается.<br>E2. [Пароль не соответствует требованиям: меньше 8 символов, нет цифры]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система показывает требования к паролю.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 1 подпотока S1.<br>E3. [Адрес уже зарегистрирован]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система предлагает войти или восстановить пароль.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 1 основного потока.<br>E4. [Неверные учётные данные]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система сообщает об ошибке; после 5 неудачных попыток вход блокируется на 15 минут.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 1 подпотока S2.<br>E5. [Почтовый сервис недоступен]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система ставит отправку письма в очередь на повтор и сообщает, что письмо придёт позже. |
| Подпотоки | S1. [Выбрана регистрация] — «Регистрация учётной записи»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Пользователь вводит e-mail и пароль (E1, E2).<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Система проверяет уникальность адреса (E3).<br>&nbsp;&nbsp;&nbsp;&nbsp;3. Система создаёт учётную запись на бесплатном тарифе.<br>&nbsp;&nbsp;&nbsp;&nbsp;4. S4 // Отправка письма пользователю (подтверждение адреса)<br>&nbsp;&nbsp;&nbsp;&nbsp;5. Система сообщает о необходимости подтвердить адрес.<br>S2. [Выбран вход] — «Вход по e-mail и паролю»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Пользователь вводит e-mail и пароль (E1).<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Система проверяет учётные данные (E4).<br>&nbsp;&nbsp;&nbsp;&nbsp;3. S5 // Выдача токенов доступа<br>&nbsp;&nbsp;&nbsp;&nbsp;4. Система открывает главное окно.<br>S3. [Нажата «Забыли пароль?»] — «Восстановление пароля»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Пользователь вводит e-mail (E1).<br>&nbsp;&nbsp;&nbsp;&nbsp;2. S4 // Отправка письма пользователю (ссылка сброса)<br>&nbsp;&nbsp;&nbsp;&nbsp;3. Пользователь переходит по ссылке и вводит новый пароль (E2).<br>&nbsp;&nbsp;&nbsp;&nbsp;4. Система сохраняет новый пароль и аннулирует старые токены.<br>S4. «Отправка письма пользователю»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система формирует письмо по шаблону.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Система передаёт письмо почтовому сервису (E5).<br>S5. «Выдача токенов доступа»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система выдаёт токен доступа JWT (15 минут) и токен обновления (30 дней). |
| Приоритет (Критично | Важно | Желательно) | Критично |
