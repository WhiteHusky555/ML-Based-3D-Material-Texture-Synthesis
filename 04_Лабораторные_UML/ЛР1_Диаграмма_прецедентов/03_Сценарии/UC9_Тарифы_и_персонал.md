# UC9. Описание прецедента «Управление тарифами и персоналом»

| Поле | Содержание |
|---|---|
| Название | S1. Реализация прецедента «Управление тарифами и персоналом» |
| Действующие лица | Владелец |
| Краткое описание | Владелец изменяет цены и лимиты тарифов, назначает и отзывает роли сотрудников, получает финансовый отчёт. |
| Предусловия | Владелец вошёл в систему. |
| Постусловия | Изменения сохранены и записаны в журнал аудита либо владелец получил финансовый отчёт. |
| Основной поток | 1. Система отображает панель владельца с разделами: Тарифы, Персонал, Финансы.<br>2. Владелец выбирает раздел и действие (точка расширения «Выбор раздела»).<br>3. S1 [Выбран раздел «Тарифы»] // Изменение цен и лимитов тарифов<br>4. S2 [Раздел «Персонал», нажата «Назначить роль»] // Назначение роли сотруднику<br>5. S3 [Раздел «Персонал», нажата «Отозвать роль»] // Отзыв роли сотрудника<br>6. S4 [Выбран раздел «Финансы»] // Формирование финансового отчёта<br>7. Пункты 1–6 повторяются, пока владелец не закроет панель.<br>8. Выполнение прецедента завершается. |
| Альтернативные потоки | A1. [Изменяется цена тарифа, по которому есть активные подписки]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система предупреждает, что для действующих подписок новая цена применяется со следующего периода оплаты.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 3 подпотока S1. |
| Потоки ошибок | E1. [Значение лимита вне допустимого диапазона]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система показывает допустимые значения.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 2 подпотока S1.<br>E2. [Учётная запись с указанным e-mail не найдена]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система сообщает, что сотрудник должен сначала зарегистрироваться.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 1 подпотока S2.<br>E3. [Попытка отозвать роль владельца]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система запрещает действие: в системе всегда должен оставаться владелец.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 1 основного потока. |
| Подпотоки | S1. «Изменение цен и лимитов тарифов»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Владелец выбирает тариф.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Владелец изменяет цену, период оплаты и права тарифа: генераций в сутки, разрешение, шаги, число вариантов, срок хранения (E1, A1).<br>&nbsp;&nbsp;&nbsp;&nbsp;3. Система сохраняет новую версию тарифа: лимиты действуют для новых задач без перевыпуска программы, цена — с нового периода оплаты.<br>&nbsp;&nbsp;&nbsp;&nbsp;4. S6 // Запись в журнал аудита<br>S2. «Назначение роли сотруднику»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Владелец вводит e-mail существующей учётной записи (E2) и выбирает роль: «администратор» или «аналитик».<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Система сохраняет роль; права действуют со следующего запроса сотрудника.<br>&nbsp;&nbsp;&nbsp;&nbsp;3. S6 // Запись в журнал аудита<br>S3. «Отзыв роли сотрудника»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Владелец выбирает сотрудника и подтверждает отзыв роли (E3).<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Система снимает роль.<br>&nbsp;&nbsp;&nbsp;&nbsp;3. S5 // Аннулирование сеансов сотрудника<br>&nbsp;&nbsp;&nbsp;&nbsp;4. S6 // Запись в журнал аудита<br>S4. «Формирование финансового отчёта»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Владелец задаёт период.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Система показывает выручку, число платежей и возвратов, число активных подписок, средний доход на пользователя и отток подписчиков; отчёт можно выгрузить в CSV.<br>S5. «Аннулирование сеансов сотрудника»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система отзывает токены обновления сотрудника и увеличивает версию его токенов: следующий запрос с прежним токеном доступа отклоняется.<br>S6. «Запись в журнал аудита»<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система сохраняет запись: сотрудник, время, действие, объект, старое и новое значение. |
