# СЦ4. Сценарий взаимодействия Платёжной системы с системой

| Поле | Содержание |
|---|---|
| Название | Сценарий оплаты премиум-подписки платёжной системой |
| Действующие лица | Платёжная система |
| Краткое описание | Платёжная система принимает запрос на оплату подписки, проводит платёж пользователя и сообщает системе результат уведомлением (webhook). |
| Предусловия | Пользователь выбрал оформление премиум-подписки; система создала платёж. |
| Постусловия | Система получила подтверждённый результат платежа. |
| Основной поток | 1. Платёжная система получает от системы запрос на оплату: сумма, назначение, идентификатор платежа.<br>2. Платёжная система показывает пользователю страницу оплаты.<br>3. Пользователь вводит платёжные данные на стороне платёжной системы.<br>4. Платёжная система проводит платёж (E1).<br>5. Платёжная система отправляет системе уведомление о результате с цифровой подписью.<br>6. Система проверяет подпись уведомления (E2) и активирует подписку.<br>7. Выполнение сценария завершается. |
| Альтернативные потоки | A1. [Пользователь закрыл страницу оплаты]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Платёжная система отменяет платёж по истечении срока и уведомляет систему.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 7. |
| Потоки ошибок | E1. [Платёж отклонён]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Платёжная система уведомляет систему об отказе; подписка не активируется.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 7.<br>E2. [Подпись уведомления неверна]<br>&nbsp;&nbsp;&nbsp;&nbsp;1. Система отклоняет уведомление и записывает событие в журнал безопасности.<br>&nbsp;&nbsp;&nbsp;&nbsp;2. Переход к пункту 7. |
| Подпотоки | Подпотоков нет. |
| Приоритет (Критично | Важно | Желательно) | Важно |
| Частота использования (Всегда | Часто | Иногда | Редко | Один раз) | Иногда |
