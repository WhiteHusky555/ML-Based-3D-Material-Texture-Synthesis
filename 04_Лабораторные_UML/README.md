## Общие требования (из [5], «Общие замечания»)
- **Проектное решение выражается моделью, а не диаграммой.** Диаграммы — часть модели.
- **Документируется всё:** сама диаграмма (секция Documentation при отсутствии выделения) и **все** её элементы — узлы и стрелки.
- Пояснения в отчёте делятся на части: «Документирование акторов», «…прецедентов», «…действий и деятельностей», «…состояний», «…отношений», «…переходов».
- **Отчёт** — doc/docx с титулом по Приложению А [5]. Содержит: 1) название темы; 2) формулировку задания; 3) экспорт диаграмм в графические файлы; 4) тексты документирования; 5) описания потоков реализации прецедентов.
- **Теорию и методические указания в отчёт не включать.**
- Объём по теме — ориентир до 30 страниц; если документирование всего не помещается, можно ограничиться несколькими диаграммами.
- Каждая тема защищается, лучше всего публичным докладом с показом отчёта.
- Методичка Каюмовой [6] содержит ошибки (две главы 6) — использовать в основном как руководство по интерфейсу StarUML.

## Инструмент
Работаю в **StarUML 6.3.3** (проекты `.mdj`); каждый проект сохраняется также в формате **StarUML 5.0** (`.uml`), интерфейс которого описан в методичке. Подробно о версиях — [ЛР0](ЛР0_Среда_StarUML/README.md).

## Папка `_инструменты`
- `staruml_mdj.py` — сборка проекта StarUML 6.x (.mdj) из описания модели на Python (диаграммы прецедентов);
- `staruml_xpd.py` — то же для StarUML 5.0 (.uml, формат XPD);
- `activity.py` — диаграммы деятельности: раскладка по дорожкам, ортогональные переходы, подписи условий; запись в оба формата;
- `statemachine.py` — диаграммы автомата (состояния с entry/do/exit, ссылочные состояния, выбор и соединение) на той же раскладке;
- `classdiagram.py` — диаграммы классов: классы с атрибутами и операциями, пакеты, ассоциации / агрегации / композиции, зависимости со стереотипами, обобщения и реализации; ортогональные линии, подписи и кратности; запись в оба формата;
- `mdj_render.py` (+ `act_render.py`, `class_render.py`) — рисунки SVG/PNG из `.mdj` по правилам отрисовки StarUML 6 и автоматическая проверка раскладки (`--check`; фильтры `--activity`, `--statechart`, `--classes`);
- формат сверен с метамоделью StarUML 6.3.3 и с примерами/исходниками StarUML 5.0 из раздаточного архива.

**Модель одна на весь курс**: каждая работа дополняет проект предыдущей (ЛР2 = модель ЛР1 + Logical View с деятельностями; ЛР3 = ЛР2 + пакет «Автоматы»; ЛР4 = ЛР3 + пакет «Классы»), поэтому актуальный файл проекта — файл последней работы.
