# Процедурный сервис — NumPy + Numba

## Два режима одного образа
| Развёртывание | Что делает | Масштабирование |
|---|---|---|
| `procedural-api` | `GET /noise/preview?type=…&cells=…&octaves=…&stretch=…&seed=…` → WebP 256² или 512² (для ползунков). Async FastAPI; расчёт Numba — в `ProcessPoolExecutor`, чтобы не блокировать event loop | HPA по CPU |
| `procedural-worker` | Celery-задача `noise` из очереди `noise`: карта высот любого разрешения (PNG 16 бит) → S3. Используется в конвейере (512² для ControlNet) и для PBR (итоговое разрешение) | KEDA по длине очереди |

Код алгоритмов общий, различается только точка входа.

## Алгоритмы
- Перлин (градиентный шум) с fBm (октавы).
- Вороной F1 (булыжник, ячейки) и F2−F1 (трещины, швы).
- Domain warping — искажение координат шумом.
- Растяжение по осям (кора, волокна).

## Условия бесшовности (прямо перечислить в тексте ВКР)
1. Решётка Перлина периодическая: индексы узлов берутся по модулю числа ячеек.
2. В fBm множитель частоты между октавами **только целый** (×2), иначе октавы перестают укладываться в плитку.
3. Вороной: расстояние на торе — `min(|dx|, T − |dx|)`.
4. Domain warping: поле смещений тоже строится из периодического шума.
5. Растяжение — целое отношение числа ячеек по осям.

## Независимость от разрешения
С тем же seed карта высот пересчитывается сразу в 2048² или 4096², а не растягивается из 512². Это главный аргумент за Numba: на больших разрешениях скорость начинает решать (сравнение технологий — слайд 9 презентации).

## Numba
- `@njit(parallel=True, cache=True)`, `prange` по строкам.
- JIT прогревается при старте; healthcheck отвечает «готов» только после прогрева.
- `NUMBA_CACHE_DIR` — на volume, чтобы не компилировать заново после перезапуска контейнера.

## Идея на будущее
Генератор раскладки «кирпич / плитка / паркет» с шумовым искажением. Вороной даёт булыжник и трещины, но прямоугольную брусчатку, кирпич и плитку из него не получить, а это одни из самых частых материалов.
