# Запросы с номерами, цепочки запросов и публикация по ссылке; pepper для паролей

Принято 01.11.2026. Влияет на ЛР1–ЛР4 и на сервисы: API-сервис ([03](03_API-сервис_оркестратор.md)), сервис пользователей ([09](09_Сервис_пользователей_и_тарифы.md)), веб-клиент ([02](02_Веб-клиент.md)).

## Что меняется для пользователя
- Генератор работает как диалог: пользователь описывает материал и получает результат, а затем уточняет его («сделай мшистее», «крупнее камни»). Каждое уточнение — новый **запрос** в той же **цепочке**.
- У каждого запроса есть **номер в аккаунте** («Запрос №17») и **код** («R-7F3K-9Q2M»). Номер удобен человеку в своей истории, код называют поддержке и видят в ссылке.
- Цепочку можно **опубликовать по ссылке** и отправить другу, как чат в ИИ-сервисах. Друг (**гость**, без входа) видит снимок цепочки: описания, параметры, превью и 3D-просмотр.
- Если у друга есть учётная запись, он нажимает **«Продолжить у себя»** (без входа система сначала предложит войти или зарегистрироваться). В его аккаунте появляется **копия цепочки**: те же шаги с описаниями, параметрами и миниатюрами. Дальше он уточняет любой шаг или запускает генерацию заново — уже своими запросами, по своему тарифу и квоте.
- Ссылку можно **отозвать** — после этого она перестаёт открываться сразу.

## Запрос на генерацию
- Создаётся при каждом нажатии «Сгенерировать» или «Уточнить», если права тарифа подтверждены. Хранится и тогда, когда результат выдан из кэша, когда генерация упала или её отменили — это история пользователя и данные для аналитики. Отказ по квоте или параметрам запросом не становится: номер не тратится, пользователь видит причину отказа.
- **Номер в аккаунте** — 1, 2, 3… отдельно у каждого пользователя. Выдаётся атомарным увеличением счётчика `request_counters.last_number` в той же транзакции, что и вставка запроса (через ORM). Уникальность `(user_id, number)` — ограничение в БД. Номер не раскрывает, сколько запросов во всём сервисе.
- **Код** — `R-` и 8 символов Crockford Base32 из 40 случайных бит (`secrets`), уникальный индекс; при совпадении код генерируется заново. Код случайный, поэтому чужие запросы по нему не перебрать. Доступ к запросу всё равно проверяется по владельцу.
- **Идемпотентность:** повтор `POST` с тем же ключом идемпотентности возвращает уже созданный запрос — второй номер не выдаётся.
- Связь с материалами: запрос даёт 1–4 материала (варианты) или ссылается на готовый материал из кэша. Статус обработки по-прежнему хранится в материале (автомат ЛР3 «Обработка задачи генерации»), статус запроса — сводный: `в работе`, `готово`, `ошибка`, `отменён`.
- **Уточнение** — новый запрос в той же цепочке со ссылкой на предыдущий (`parent_id`); параметры копируются из предыдущего и меняются.

## Цепочка запросов
- Принадлежит пользователю. Номера нет, есть **название**: по умолчанию — первые 60 символов первого описания, можно переименовать.
- Содержит запросы по порядку номеров. Удаление цепочки удаляет её запросы и неиспользуемые материалы, а также отзывает ссылку на неё.
- История (UC5) показывает список цепочек; внутри цепочки — её запросы с номерами, кодами, превью и сроками хранения.

## Публикация по ссылке
- `POST /api/chains/{id}/share` создаёт **снимок** цепочки на момент публикации. Снимок содержит название, описания, параметры, ключи превью и карт; e-mail, идентификатор пользователя и другие личные данные в снимок не попадают. Новые запросы в цепочке в ссылке не появятся, пока пользователь не обновит снимок.
- **Токен ссылки** — 128 случайных бит (`secrets.token_urlsafe(16)`), показывается один раз в адресе `/s/<токен>`. В БД хранится только SHA-256 токена, поэтому утечка базы не даёт рабочих ссылок. У цепочки не больше одной действующей ссылки. «Обновить снимок» заменяет содержимое по тому же адресу (друзьям не нужна новая ссылка); после отзыва старый адрес не оживает, новая публикация выдаёт новый токен.
- **Отзыв** — `DELETE /api/chains/{id}/share` ставит `revoked_at`. Ссылка проверяется при каждом открытии, кэша нет, поэтому отзыв действует сразу.
- **Гость** (`GET /s/<токен>`, без входа) видит снимок, превью и 3D-просмотр с картами уменьшенного разрешения по временным ссылкам S3. Скачивания и экспорта нет: лицензия премиум-материалов коммерческая, а гостевой трафик ограничен. Ограничение частоты запросов на шлюзе, `noindex`, строгий CSP.
- Если файлы материала удалены по сроку хранения, снимок показывает параметры, а вместо 3D — «файлы удалены».
- **«Продолжить у себя»** (`POST /api/shared/<токен>/copy`, требует входа) создаёт у вошедшего пользователя **новую цепочку — копию снимка**:
  - шаги снимка переносятся как **предыстория** цепочки: описание, параметры, миниатюра и код исходного запроса. Это не запросы друга: номера им не выдаются, квота не тратится, генерации не было;
  - миниатюры копируются в хранилище друга (несколько десятков КБ на шаг), чтобы его копия не зависела от сроков хранения у автора; полноразмерные карты не копируются — лицензия и место;
  - название копии — название исходной цепочки с пометкой «копия»; ссылка на источник хранится, но имя и e-mail автора — нет;
  - продолжение — обычный UC2: «Уточнить» на любом шаге предыстории создаёт **запрос** в копии (с номером в аккаунте друга и новым кодом), параметры копируются с выбранного шага. Параметры, недоступные на тарифе друга, показываются как нарушения (`ПраваТарифа.НайтиНарушения()`) до запуска;
  - повторное нажатие с тем же ключом идемпотентности не создаёт вторую копию. Отзыв ссылки уже сделанные копии не удаляет: друг получил снимок, как скачанный файл.
- Публикации и открытия ссылок учитываются в аналитике обезличенно (сколько публикаций и открытий, сколько повторов).

## Сравнение с ИИ-сервисами
Схема публикации сверена с ChatGPT, Claude и Gemini — подробно в [20](20_Публикация_чатов_в_ИИ-сервисах.md). Совпадает с ChatGPT и Gemini: снимок, продолжение в отдельной копии, отзыв не удаляет уже сделанные копии. При публикации пользователь видит предупреждение: ссылку может открыть любой, у кого она есть.

## Пароли: соль и pepper
- **Соль** отдельно не хранится: Argon2id записывает результат строкой PHC `$argon2id$v=19$m=…,t=…,p=…$<соль>$<хэш>`. Соль случайная для каждого пароля (16 байт), параметры алгоритма — в той же строке.
- **Pepper** — секрет 32+ случайных байта в переменных окружения `PASSWORD_PEPPER_V1`, `PASSWORD_PEPPER_V2`, … и номер текущей версии `PASSWORD_PEPPER_CURRENT`. Значения передаются через Kubernetes Secret, в репозиторий, логи и базу не попадают. Хэш считается так: `Argon2id(HMAC-SHA256(pepper, пароль))`.
- `users.pepper_version` — какой версией pepper посчитан хэш. При входе, если версия pepper или параметры Argon2 устарели, пароль перехешируется текущими. Старая версия pepper удаляется из окружения, когда в базе не осталось хэшей с ней.
- Хеширование — отдельный класс сервиса пользователей (`ХэшированиеПаролей` в ЛР4), сущность «Пользователь» хранит только строку хэша и версию pepper.
- Потеря pepper делает все хэши непроверяемыми; вход восстанавливается через «Восстановление пароля». Поэтому pepper хранится в резервной копии секретов вместе с ключами платёжной системы.

## API (дополнение к [03](03_API-сервис_оркестратор.md))
| Метод и путь | Назначение |
|---|---|
| `POST /api/requests` | новый запрос: в новой цепочке или уточнение (`chain_id`, `parent_id`); ответ `202` с номером, кодом и id материалов |
| `GET /api/chains` | список цепочек пользователя (постранично) |
| `GET /api/chains/{id}` | запросы цепочки с номерами, кодами, статусами и материалами |
| `PATCH /api/chains/{id}` | переименовать цепочку |
| `DELETE /api/chains/{id}` | удалить цепочку |
| `GET /api/requests/by-code/{code}` | найти свой запрос по коду; администратору — любой (поддержка) |
| `POST /api/chains/{id}/share` | опубликовать или обновить снимок, выдать ссылку |
| `DELETE /api/chains/{id}/share` | отозвать ссылку |
| `GET /s/{token}` | гостевая страница снимка (без входа) |
| `POST /api/shared/{token}/copy` | «Продолжить у себя»: копия цепочки в аккаунте вошедшего пользователя |

## Таблицы (схема `core`)
- `request_chains` (id, user_id, title, copied_from_link_id NULL, created_at, updated_at)
- `chain_history` (chain_id, position, description, params jsonb, thumbnail_s3_key, source_code) — предыстория копии: шаги снимка, перенесённые при «Продолжить у себя»
- `generation_requests` (id, user_id, chain_id, number, code, parent_id, params jsonb, status, idempotency_key, created_at); уникальные `(user_id, number)`, `code`, `(user_id, idempotency_key)`
- `request_materials` (request_id, material_id, from_cache) — какие материалы дал запрос
- `request_counters` (user_id, last_number) — выдача номеров
- `shared_links` (id, chain_id, user_id, token_hash, snapshot jsonb, created_at, revoked_at); уникальный `token_hash`, не больше одной действующей ссылки на цепочку
- В схеме `users`: `users.pepper_version`.
