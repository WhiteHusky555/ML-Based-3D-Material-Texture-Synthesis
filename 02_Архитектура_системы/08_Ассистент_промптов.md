# Ассистент промптов — всплывающие подсказки (премиум)

## Как выглядит для пользователя
- Пользователь пишет описание или правит промпт; после паузы ~1 с появляется всплывающее окно.
- В окне 1–3 варианта, каждый с кнопкой «Применить»:
  - перевести на английский и дополнить деталями материала (CLIP в SD 1.5 понимает только английский);
  - убрать мешающие слова («фото крупным планом» → перспектива и тени);
  - добавить характерные детали;
  - выбрать подходящий **пресет шума** (форма материала).
- Окно можно закрыть; генерация подсказок не ждёт.
- **Это не чат и не диалог:** один запрос — один ответ, история не хранится.
- **Доступно на премиум-тарифе.** Бесплатному — плашка «Подсказки доступны в Премиум» (вариант: 3 подсказки в сутки как пробник — решить, см. [11](11_Решения_и_вопросы.md)).

## API
`POST /api/assistant/suggest`
```json
// запрос
{"text": "кора старого дуба, фото крупным планом", "mode": "simple",
 "preset": "stone", "modifiers": [], "noise": {"type": "vf1", "cells": 10}}
// ответ
{"suggestions": [
  {"kind": "rewrite", "title": "Перевести на английский и дополнить",
   "prompt": "old oak tree bark, deep vertical grooves, lichen patches"},
  {"kind": "remove", "title": "Убрать «фото крупным планом»", "fragment": "фото крупным планом"},
  {"kind": "preset", "title": "Выбрать пресет «Кора»", "preset": "bark"}
]}
```

## Почему ответ строго по JSON-схеме
- Pydantic-схема: `kind` — из списка (`rewrite`, `add`, `remove`, `preset`), `preset` — только существующий.
- Ollama и llama.cpp ограничивают вывод JSON-схемой → синтаксически битого JSON не бывает. Семантическая ошибка → один повтор с текстом ошибки, иначе подсказка отбрасывается.
- Обязательные части промпта и negative prompt всё равно добавляет шаблон; итоговая длина проверяется токенизатором CLIP (≤ 77 токенов).

## Где работает модель
Решение автора: **локальная модель или OpenRouter**. Полный разбор провайдеров, включая российские (GigaChat, открытые T-Lite / T-Pro, GigaChat 3.x, YandexGPT 5 Lite), — в [14_LLM-провайдеры_для_подсказок.md](14_LLM-провайдеры_для_подсказок.md).

- В коде — интерфейс `LLMProvider`; Ollama, vLLM и OpenRouter работают через один OpenAI-совместимый клиент, GigaChat — через отдельный адаптер.
- Можно задать основной и резервный провайдер, а также более сильную модель для премиума.
- В облаке на GPU-узле g6.xlarge (L4 24 ГБ) рядом с SD остаётся место под модель 3–8B — ответ за 1–2 с.

Исходный вариант (видеокарта 8 ГБ, локальная разработка):
- **Ollama** в отдельном контейнере, по умолчанию **на CPU**: видеокарта занята SD + ControlNet, а 7–8B модель потребовала бы ещё ~5 ГБ.
- Модель на **3–4 млрд параметров** с хорошим русским и поддержкой structured output (семейства Qwen, Gemma и т. п.; конкретную версию выбрать при реализации).
- Ориентир на CPU: **5–20 с** на ответ; длинный системный промпт кэшируется рантаймом.
- При видеокарте 12+ ГБ — та же модель на GPU, 1–2 с.
- Ollama даёт **OpenAI-совместимый API** → один клиент и для локальной модели, и для внешнего провайдера.
- Для премиума можно использовать более сильную модель (больше параметров или внешний провайдер) — решается конфигурацией.

## Устройство
- FastAPI; без RabbitMQ — интерактивный запрос-ответ.
- Кэш ответов по хэшу текста + контекста (Redis не нужен: in-memory LRU или таблица в PostgreSQL).
- Проверка тарифа по `X-User-Plan` от шлюза; счётчик подсказок — у сервиса пользователей (если будет пробный лимит).
- Ограничения: текст до 1000 символов, таймаут 60 с, лимит частоты в nginx.
- **Деградация:** модель недоступна → подсказки просто не появляются, остальное работает.

## Метрики для ВКР
- время ответа (CPU / GPU, 2–3 размера модели);
- доля ответов, прошедших схему с первой попытки;
- доля принятых подсказок;
- CLIP score текстур до и после принятия подсказок.
