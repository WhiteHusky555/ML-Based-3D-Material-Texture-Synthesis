# API-сервис (оркестратор) — FastAPI

Владелец материалов и задач генерации. Пользователей и тарифы не хранит — получает `X-User-Id`, `X-User-Plan` и `X-User-Role` от BFF. Права тарифов держит локальной копией, её обновляет событие `plan.changed` от сервиса пользователей (решение 13.11.2026, [24](24_Асинхронное_взаимодействие_outbox_inbox.md)).

## Эндпоинты и команды
Внутренний API сервиса: снаружи его вызывают только web-bff и staff-ui ([17](17_Предложение_внедрения_BFF.md), [23](23_Vaadin_для_интерфейса.md)), гость — через гостевые маршруты web-bff.
- **Чтение** (`GET`, WebSocket) — по HTTP.
- **Команды** (строки `POST`, `PATCH`, `DELETE`) с 13.11.2026 приходят сообщениями из обмена `commands` с ключом `core.<команда>` (например, `core.request.create`). Id сущности, он же ключ идемпотентности, создаёт BFF и сразу отвечает клиенту `202`. Сервис обрабатывает команду через inbox, итог публикует событием ([24](24_Асинхронное_взаимодействие_outbox_inbox.md)).

| Метод и путь | Назначение |
|---|---|
| `POST /api/requests` | создать запрос на генерацию в цепочке (новой или существующей, с уточнением предыдущего); номер в аккаунте и код — см. [19](19_Запросы_цепочки_и_публикация.md) |
| `GET/PATCH/DELETE /api/chains[/{id}]` | цепочки запросов пользователя: список, запросы цепочки, переименование, удаление |
| `POST/DELETE /api/chains/{id}/share` | опубликовать или обновить снимок цепочки по ссылке; отозвать ссылку |
| `GET /s/{token}` | гостевая страница снимка (без входа) |
| `POST /api/shared/{token}/copy` | «Продолжить у себя»: копия цепочки в аккаунте вошедшего пользователя |
| `POST /api/materials` | создать задачу генерации (вызывается из `POST /api/requests`) |
| `GET /api/materials/{id}` | статус, ссылки на карты |
| `GET /api/materials` | история пользователя (постранично) |
| `DELETE /api/materials/{id}` | удалить материал / отменить задачу |
| `GET /api/materials/{id}/download?engine=unity` | ZIP под движок (presigned-ссылка MinIO) |
| `GET /api/presets` | пресеты материалов |
| `WS /ws/jobs/{id}` | прогресс задачи |
| `GET /api/analytics/generations?from=&to=` | агрегаты по генерациям: пресеты, время этапов, доля кэша, отмены и ошибки (роли analyst, owner; вызывает admin-service) |

Пресеты и версии модели с 13.11.2026 принадлежат `admin-service` ([22](22_Kotlin_и_Ktor_для_администрирования.md)). API-сервис держит копию пресетов для генератора и номер текущей версии модели, обновляя их по событиям `preset.changed` и `model_version.published`.

## Обработка команды `core.request.create` (создание материала)
0. **Inbox:** id сообщения записывается в таблицу `inbox` в той же транзакции, что и шаги 3–4. Повтор команды — дубль: подтвердить и ничего не делать.
1. **Проверка прав тарифа** (entitlements): разрешение, модель, число вариантов, суточная квота. Нарушение → событие `job.<id>.rejected` с понятным текстом («4096² доступно в Премиум», «лимит 10 генераций на сегодня исчерпан»); web-bff показывает его как раньше `403` / `429`.
2. **Кэш по хэшу** параметров. Хэш: шум + промпт + seed + разрешение + версии SD / ControlNet / LoRA / апскейлера + версия кода конвейера.
   - Бесплатные пользователи используют **общий кэш** — экономия GPU.
   - **Премиум-результаты в общий кэш не попадают** (в ключ входит `user_id`): у премиума коммерческая лицензия без атрибуции, его материалы не должны доставаться другим.
3. Запись материала с `expires_at` = сейчас + срок хранения тарифа.
4. **Outbox:** в той же транзакции — строка в таблице `outbox` «поставить цепочку». Ретранслятор ставит Celery-цепочку `noise → generate → upscale → pbr`: очереди `noise`, `gpu`, `cpu`, **приоритет по тарифу** (премиум выше). Шум тоже считается в очереди — API-сервис ничего не ждёт. Запись материала и постановка цепочки больше не расходятся при сбое.
5. **Событие `job.<id>.accepted`** (тоже через outbox). `202` с id клиент получил от web-bff ещё до обработки; дальше прогресс идёт по WebSocket.

Сервис полностью асинхронный: async FastAPI, asyncpg, aio-pika. Состояния в памяти нет, поэтому реплик может быть сколько угодно (см. [12](12_Kubernetes_и_асинхронность.md)).

## Состояния задачи
`created → noise → generating → upscaling → pbr → done / failed / cancelled`.
Время входа в каждый этап пишется в таблицу `stages` — из неё берутся метрики ВКР.

## Поэтапный кэш
Отдельные хэши: шума, генерации, PBR-настроек. Поменяли только силу нормалей — пересчитывается один PBR-этап за секунды, GPU не нужен.

## События
- Воркеры публикуют в topic-exchange `job.events` (routing key `job.<id>.<stage>`).
- **Запись в БД:** общая durable-очередь `status-updates`, которую слушают все реплики как конкурирующие потребители — каждое событие записывается ровно один раз.
- **WebSocket** клиента проксирует web-bff: соединение с API-сервисом приходит от BFF с заголовком `X-User-Id`.
- **Доставка в WebSocket:** у каждой реплики своя временная очередь; когда клиент открывает сокет для задачи, реплика привязывает очередь к `job.<id>.#`. Событие приходит туда, где открыт сокет, — «липкие» сессии не нужны.
- **В таблицы материалов пишет только API-сервис**, воркеры в базу не ходят: у данных один владелец.
- Запись события этапа идемпотентна по паре (задача, этап) и не откатывает статус назад: событие может прийти повторно или позже следующего.
- **Исходящие события через outbox** (обмен `domain.events`): `job.completed` и `hint.used` → сервис пользователей (учёт использования вместо `POST /internal/usage`), записи аудита → `admin-service`, события публикации и копирования цепочек.

## Срок хранения
- **Kubernetes CronJob** (раз в час) находит материалы с `expires_at < now()`, удаляет объекты из S3 и строки из БД, публикует событие. Celery beat не используется: при нескольких репликах он запускал бы задачу несколько раз.
- При оформлении премиума у существующих материалов пользователя `expires_at` продлевается до срока премиума; при отмене — возвращается к сроку бесплатного тарифа, считая от даты отмены (уточнить правило в [11_Решения_и_вопросы.md](11_Решения_и_вопросы.md)).

## Таблицы (схема `core`)
- `materials` (id, user_id, params jsonb, params_hash, plan_at_creation, status, created_at, expires_at)
- `stages` (material_id, stage, started_at, finished_at, gpu_mem_peak, worker)
- `artifacts` (material_id, kind, s3_key, width, height, format, bytes)
- `presets` (id, name, noise jsonb, prompt_template, base_roughness, premium_only, version) — копия, владелец `admin-service`
- `plan_rights` (plan, …, version) — копия прав тарифов, владелец — сервис пользователей
- `outbox`, `inbox` — служебные таблицы, см. [24](24_Асинхронное_взаимодействие_outbox_inbox.md)
- `request_chains`, `chain_history`, `generation_requests`, `request_materials`, `request_counters`, `shared_links` — запросы, цепочки и публикация, см. [19](19_Запросы_цепочки_и_публикация.md)
- Миграции — Alembic.

## Очереди сервисного стенда НИР

API принимает задание, возвращает идентификатор и предоставляет статус. В стенде НИР это POST /jobs с Idempotency-Key и GET /jobs/{id}. В дипломной системе за фиксацию задания и постановку отвечает outbox API-сервиса.
