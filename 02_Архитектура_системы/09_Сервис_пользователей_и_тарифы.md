# Сервис пользователей и тарифов

Решение (14.10.2026): **пользователи хранятся всегда** — под будущую монетизацию. Премиум-пользователь получает лучшее качество (больше шагов и вариантов, референсы — та же модель, без второй дообученной), большее разрешение, подсказки к промпту, долгое хранение файлов и т. д.

## Зачем отдельный сервис
- Отдельная зона ответственности: учётные записи, пароли, токены, тарифы, подписки, квоты. Не смешивается с генерацией.
- Один владелец таблиц пользователей (схема `users` в PostgreSQL).
- Шлюз проверяет токены через него (`auth_request`), остальные сервисы получают готовые `X-User-Id`, `X-User-Plan`.

## Функции
| Функция | Эндпоинты |
|---|---|
| Регистрация, подтверждение e-mail | `POST /api/auth/register`, `POST /api/auth/confirm` |
| Вход, выход, обновление токена | `POST /api/auth/login`, `/logout`, `/refresh` |
| Восстановление пароля | `POST /api/auth/reset` |
| Проверка токена для шлюза | `GET /internal/auth/verify` |
| Профиль, тариф, остаток квот | `GET /api/me` |
| Оформление / отмена премиума | `POST /api/billing/subscribe`, `POST /api/billing/cancel` |
| Уведомления платёжной системы | `POST /api/billing/webhook` |
| Права тарифа для других сервисов | `GET /internal/plans/{plan}` |
| Учёт использования | `POST /internal/usage` (генерации, подсказки) |
| Администрирование (admin) | `GET /api/admin/users`, `POST /api/admin/users/{id}/block`, `/unblock`, `/plan` — поиск, блокировка, ручной тариф |
| Тарифы и персонал (owner) | `PUT /api/owner/plans/{code}`, `PUT /api/owner/staff/{user_id}` (назначить роль), `DELETE /api/owner/staff/{user_id}` (отозвать), `GET /api/owner/finance`, `GET /api/owner/audit` |
| Аналитика (analyst, owner) | `GET /api/analytics/{report}?from=&to=` — агрегаты по пользователям и подпискам; показатели генераций отдаёт API-сервис |

## Роли и права
Решение (16.10.2026): кроме пользователей в системе работают три роли персонала. Роль одна на учётную запись.

| Возможность | user | admin | analyst | owner |
|---|---|---|---|---|
| Генерация, история, экспорт, подписка | да | да | да | да |
| Поиск пользователей, блокировка, ручной тариф | — | да | — | — |
| Пресеты, загрузка версий LoRA (API-сервис) | — | да | — | — |
| Технический мониторинг (Grafana) | — | да | — | да |
| Аналитика: агрегаты без персональных данных | — | — | да | да |
| Цены и лимиты тарифов | — | — | — | да |
| Назначение и отзыв ролей admin / analyst | — | — | — | да |
| Финансовый отчёт, журнал аудита | — | — | — | да |

- **Администратор** — техническое обслуживание: пользователи, пресеты, модели, мониторинг. Цены, лимиты и роли не меняет; заблокировать сотрудника не может.
- **Аналитик** — только чтение агрегатов: e-mail и идентификаторы в отчёты не попадают, группы меньше 5 пользователей сливаются в «прочие».
- **Владелец** — коммерческие решения и персонал. Учётная запись создаётся при развёртывании командой `python -m users.bootstrap_owner` (e-mail из переменной окружения `OWNER_EMAIL`, пароль задаётся по ссылке из письма); роль владельца нельзя отозвать через интерфейс, чтобы в системе всегда оставался владелец.
- **Проверка прав — на сервере при каждом запросе.** Шлюз вызывает `/internal/auth/verify`, сервис читает из БД `status`, `role` и `token_version` и отдаёт заголовки `X-User-Id`, `X-User-Plan`, `X-User-Role`; сервисы проверяют `X-User-Role` для служебных эндпоинтов. Роль в токене не кэшируется.
- **Мгновенный отзыв:** при отзыве роли или блокировке увеличивается `token_version` и отзываются refresh-токены; следующий запрос со старым access-токеном отклоняется шлюзом (в токене есть `ver`, он не совпадает с БД).
- **Журнал аудита:** каждое изменение, сделанное персоналом (тариф, блокировка, пресет, версия модели, роль), пишется в `audit_log`; таблица только пополняется, читает её владелец.

## Безопасность
- Пароли — **Argon2id** (или bcrypt).
- Access-токен JWT — 15 мин; refresh-токен — 30 дней, в httpOnly cookie, хранится хэш в БД (можно отозвать).
- Лимит попыток входа (nginx `limit_req` + счётчик в БД).
- Персональные данные минимальны: e-mail, хэш пароля, даты. Политика конфиденциальности и согласие на обработку данных — нужны, если сервис станет публичным.

## Тарифы (предложение, значения уточняются)
| Возможность | Бесплатный | Премиум |
|---|---|---|
| Генераций в сутки | 10 | 200 (защита от злоупотреблений) |
| Итоговое разрешение | 1024² | 2048², 4096² |
| Модель генерации | одна для всех (SD 1.5 + ControlNet + LoRA), 20 шагов | та же модель, 30–40 шагов |
| Вариантов за запуск | 1 | до 4 |
| Референс-картинка (IP-Adapter) | нет | да |
| Подсказки к промпту | нет (или 3 в сутки как пробник) | да |
| Хранение файлов | 7 дней | 90 дней, пока активна подписка |
| Приоритет в очереди GPU | обычный | высокий |
| Форматы экспорта | PNG 8 бит | + 16 бит height, EXR, `.glb` |
| Лицензия на материалы | CC BY 4.0 | коммерческая без атрибуции |
| Общий кэш результатов | участвует | личный кэш (материалы не достаются другим) |

Тарифы хранятся **данными**, а не кодом: таблица `plans` с JSON-полем прав (`entitlements`). Новый тариф или изменение лимита — без перевыпуска кода. Тарифы меняет владелец; каждое изменение сохраняется новой версией в `plan_versions`.

## Таблицы (схема `users`)
- `users` (id, email, password_hash, role [user | admin | analyst | owner], status, token_version, created_at, last_login_at)
- `plans` (code [free | premium], name, price, period, entitlements jsonb)
- `subscriptions` (id, user_id, plan_code, status [active | cancelled | expired], started_at, expires_at, provider, provider_ref)
- `payments` (id, subscription_id, amount, currency, status, provider_ref, created_at)
- `usage_daily` (user_id, date, generations, suggestions)
- `refresh_tokens` (id, user_id, token_hash, expires_at, revoked)
- `audit_log` (id, actor_id, actor_role, action, object_type, object_id, old_value jsonb, new_value jsonb, created_at) — только INSERT
- `plan_versions` (plan_code, version, price, entitlements jsonb, valid_from, changed_by) — история изменений тарифов владельцем

## Оплата
- В рамках ВКР — **интерфейс платёжного провайдера + тестовая заглушка** (оплата «проходит» в тестовом режиме; также тариф может назначить вручную администратор; цены и лимиты меняет только владелец).
- Реальный провайдер подключается позже реализацией того же интерфейса (для России — например ЮKassa или CloudPayments; выбрать при запуске).
- Подписка активируется только по **webhook** провайдера (подпись проверяется), а не по возврату пользователя со страницы оплаты.

## Как тариф влияет на другие сервисы
| Сервис | Что зависит от тарифа |
|---|---|
| nginx | пробрасывает `X-User-Plan` |
| API-сервис | квоты, разрешение, модель, варианты, приоритет задачи, `expires_at`, участие в общем кэше |
| GPU-воркер | шаги, модель, апскейл до 2048/4096 |
| PBR-сервис | форматы, лицензия в manifest |
| Ассистент | доступ к подсказкам |
| MinIO / периодическая задача | удаление по сроку хранения |
