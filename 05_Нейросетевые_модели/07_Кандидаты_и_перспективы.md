# Другие упомянутые модели: кандидаты и перспективы

Эти модели обсуждались, но **в ВКР не используются**: либо лицензия не позволяет платный сервис, либо не работает наш способ бесшовности, либо пришлось бы обучать ещё одну LoRA (ограничение автора — одна обучаемая модель).
Сведения по обзорам 2026 г. (Thunder Compute, BentoML, Pinggy, Pixazo, Medium) — см. `02_Архитектура_системы/15_Модель_генерации_и_референсы.md`.

## Почему важен тип архитектуры
- **U-Net** (SD 1.5, SDXL) — свёрточная сеть → циклический padding в свёртках делает картинку бесшовной. **Наш способ работает.**
- **DiT / MMDiT** (диффузионный трансформер: SD 3.5, FLUX, Qwen-Image, Z-Image) — основная сеть работает с «патчами» через внимание, свёрток почти нет → нужен другой приём бесшовности (сдвиг латента на каждом шаге и т. п.). **Пришлось бы исследовать заново.**

## Перспективы развития (раздел ВКР)
1. **SDXL + своя LoRA** для премиума — выше качество, родное 1024².
2. Бесшовная генерация на **DiT-моделях** с открытой лицензией (Z-Image Turbo, FLUX.2 [klein]) — нужен свой метод бесшовности.
3. Генерация **сразу нескольких карт** (albedo + height + roughness) одной моделью вместо расчёта формулами.
4. **Текстурирование прямо по 3D-модели** (как Meshy) — другой класс задач.
5. **Обучение своей LoRA пользователем** внутри сервиса (как у Scenario).
