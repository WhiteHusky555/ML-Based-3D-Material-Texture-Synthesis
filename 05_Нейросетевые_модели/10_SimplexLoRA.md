# SimplexLoRA — применимость к нашей LoRA (исследование 16.11.2026)

Вопрос: годится ли SimplexLoRA для нашей нейросети — LoRA для SD 1.5, единственной обучаемой модели (НИР, [02](02_LoRA.md)).

## 1. Коротко
- **SimplexLoRA — не новая модель, а способ обучить ту же LoRA.** Он по-другому распределяет между слоями тот же общий бюджет ранга: важным слоям — больше, остальным — меньше. На выходе обычный файл LoRA, просто ранги у слоёв разные. Скорость генерации и память не меняются. Правило «обучается только одна модель» не нарушается.
- **Технически применим.** Наша LoRA стоит в линейных проекциях внимания U-Net (`to_q`, `to_k`, `to_v`, `to_out.0`) — к таким слоям метод и применяется в статье. diffusers загружает LoRA с разными рангами у слоёв штатно ([§4](#4-применимость-к-нашей-lora)).
- **Для диффузии не проверен.** В статье только текстовые модели: DeBERTaV3, BART-large, Llama 3.1 8B, Qwen3-8B. Прирост заметен при очень малом ранге (r = 1–2); при r = 8 он мал — доли процента на средней метрике. Мы планируем r = 8–32.
- **Рекомендация.** Основным методом не брать. Если хватит времени — поставить **экспериментом в НИР**: LoRA против SimplexLoRA при одинаковом бюджете (r = 4 и r = 8) на наших метриках. Заодно получится картинка, какие блоки U-Net важны для «плоской текстуры». Если времени нет — остаётся обычная LoRA, архитектура не меняется.
- **Плюс для кафедры:** авторы — российские организации (MIRAI, BRAIn Lab, SB AI Lab, Т-Технологии, Университет Иннополис), статья опубликована в Findings of EMNLP 2026.
- **Главная цена — интеграция.**
  - Код авторов — копия PEFT 0.12.1.dev0 и скрипты для языковых моделей, а нынешний diffusers требует `peft>=0.17.0`.
  - В репозитории нет файла лицензии, поэтому поиск рангов пишем сами по описанию в статье (около 100–150 строк), код не копируем. Финальное обучение — штатным скриптом diffusers с найденными рангами.

## 2. Как работает (по статье)
- **Вес важности у каждого адаптера.** Каждый из n адаптеров LoRA получает вес ωᵢ ≥ 0: `W₀ᵢ + ωᵢ·AᵢBᵢ`. Веса лежат на n-масштабированном симплексе (сумма = n); при ω = (1, …, 1) это обычная LoRA. Регуляризация `(λ/2)·‖ω − 1‖²` не даёт весам вырождаться.
- **Поиск рангов.** Три фазы повторяются K раз:
  1. разогрев: T шагов обычного обучения, A, B и ω учатся вместе;
  2. евклидова проекция ω на симплекс;
  3. новые ранги `rᵢ = ⌊r₀·ωᵢ⌋`; адаптеры, у которых ранг изменился, меняют размер и инициализируются заново (A — Kaiming, B = 0).
- **Финальное обучение (фаза 4).** ω фиксируется равным 1, A и B инициализируются заново, дальше идёт обычное обучение LoRA с найденными рангами. Веса разогрева выбрасываются — фазы 1–3 служат только поиском рангов.
- **Настройки авторов:**
  - K = 5, T = 10, то есть всего 50 шагов поиска, меньше 5 % обучения;
  - скорость обучения для ω — 5;
  - метод устойчив при K·T < 100; при K ≥ 10 или T ≥ 15 начинается «переобучение рангов».
- **Наблюдение авторов:** у DeBERTa на MRPC наибольшие ранги получают проекции value.
- **Ограничения по словам авторов:**
  - три новых гиперпараметра;
  - выигрыш зависит от задачи: на CoLA и RTE обычная LoRA не хуже;
  - малый градиент слоя может означать и «уже обучен», и «градиент затух».

## 5. Как проверить в НИР, если решим
1. **База:** обычная LoRA r = 4 и r = 8 штатным скриптом diffusers, как и планировалось.
2. **Поиск рангов — свой скрипт:**
   - LoRA через PEFT на U-Net с одинаковым рангом r₀;
   - обучаемый скаляр ωᵢ на каждый адаптер — множитель выхода адаптера;
   - K = 5 раундов по T = 10 шагов, после каждого — евклидова проекция ω на симплекс и новые ранги `rᵢ = ⌊r₀·ωᵢ⌋`.
   
   Упрощение: в каждом раунде модель с адаптерами собирается заново с новым `rank_pattern`, а ω переносится. У авторов заново инициализируются только адаптеры с изменившимся рангом — в отчёте указать это отличие.
3. **Финальное обучение:** штатный скрипт с `LoraConfig(r=r₀, rank_pattern=найденные_ранги)` и тем же числом шагов, что у базы.
4. **Сравнение** на метриках из [02](02_LoRA.md): ошибка на шве, KID, CLIP score, следование структуре шума ControlNet, поиск ближайших соседей в датасете. По возможности — 3 seed. Отдельный рисунок — распределение рангов по блокам U-Net.
5. **Объём работы:** 1–2 дня кода и 2–3 дополнительных обучения на Kaggle.

## 6. Решение (16.11.2026)
**Отказались, остаётся обычная LoRA.** Причина: мы планируем ранг 8–32, а заметный выигрыш SimplexLoRA показан при ранге 1–2; при r = 8 он в статье мал. Опытов на диффузионных моделях нет, а интеграция требует своего кода. Рассматривались варианты: только обычная LoRA (выбран), SimplexLoRA как эксперимент в НИР, SimplexLoRA вместо обычной LoRA.
