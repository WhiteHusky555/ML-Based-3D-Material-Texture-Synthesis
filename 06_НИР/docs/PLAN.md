# План НИР по обучению модели и генерации материалов

Цель — выяснить, помогает ли предметная LoRA для Stable Diffusion 1.5 получать плоские текстуры материалов по описанию, сохраняя заданную структуру и качество стыка при повторении. Основная выборка для обучения — 300–500 материалов ambientCG с лицензией CC0. Все числа ниже задают стартовый протокол. Фактический состав выборки, расход памяти и результаты предстоит измерить.

## Этапы и границы коммитов

| Этап | Результат для коммита | Проверка готовности |
|---|---|---|
| 1. Данные (§1–2) | Каталог ambientCG, правила группировки, подготовка RGB и подписей, манифест и выполненные ноутбуки аудита | Воспроизводится отбор с фиксированным seed, группы не пересекаются между частями, опубликованы числа материалов по категориям и причины исключения |
| 2. Базовая генерация (§3) | Генератор шума и ноутбук сравнения SD 1.5 с ControlNet и без него | На одинаковых промптах и seed сохранены пары изображений, повторы 2×2 и выбранные параметры управления |
| 3. Обучение (§4) | Выполненный Kaggle-ноутбук пилота и обучения LoRA, журнал и ссылка на сохранённые веса | Адаптер загружается в чистой сессии, обучение возобновляется с контрольной точки, выбор шага обоснован на validation |
| 4. Оценка (§5) | Выполненный ноутбук парных сравнений, таблицы и примеры ошибок | На зафиксированной конфигурации рассчитаны результаты для отложенных материалов |
| 5. Конвейер и передача в ВКР (§6–7) | Апскейл, PBR, сквозной пример и итоговый отчёт | По сохранённым версиям, весам и конфигурации в чистой сессии воспроизводится генерация комплекта карт |

Один завершённый этап — один содержательный коммит с кодом, тестами, документацией и выполненными ноутбуками. Промежуточные проверки входят в коммит своего этапа. Сейчас на шести материалах проверен экспорт в RGB PNG; для закрытия первого этапа нужны расширенная выборка и проверенная группировка.

## 1. Зафиксировать корпус и разбиение

- Подготовить данные в CPU-сессии Kaggle. Рабочий источник — [зеркало ambientCG](https://huggingface.co/datasets/nyuuzyou/ambientcg). Для каждой записи сохранить исходный ID, ссылку на материал, лицензию, категорию, способ получения, контрольную сумму и доступные карты.
- Включить плоские повторяемые поверхности. Представить камень, дерево, ткань, грунт и другие достаточно наполненные категории. Удалить HDRI, декали, прозрачные объекты, рендеры шаров и карты с повреждениями. Показать число материалов до и после отбора по категориям и причины исключений.
- Сгруппировать варианты одной поверхности по исходному материалу. Найти точные дубли по хешу, близкие варианты проверить по миниатюрам. До нарезки распределить группы примерно в пропорции 80/10/10 с учётом категории. Зафиксировать seed и списки ID. Если класс слишком мал для трёх частей, явно ограничить выводы по нему.
- Цель обучения — RGB-карта Color/BaseColor. Карты высот, нормалей, AO и roughness отложить для отдельных проверок конвейера. Сохранить компактную выборку для повторного подключения в Kaggle. Происхождение данных и альтернативный источник описаны в [обзоре датасетов](../../05_Нейросетевые_модели/09_База_датасет_и_дистилляция.md).

## 2. Подготовить пары «описание — цветовая карта»

Составить короткие английские подписи из категории и проверенных признаков поверхности. Например, для действительно соответствующей карты подойдёт “flat texture of light limestone with thin dark veins”. Убирать ID, названия файлов и неподтверждённые свойства. Вручную проверить примеры каждого класса. Если используем общий триггер стиля, зафиксировать его и подавать одинаковый текст базе и адаптированной модели. Для русскоязычного интерфейса хранить исходное описание и фактический английский промпт отдельно.

Для основного опыта уменьшать целую плитку до 512×512 с фильтрацией и применять случайный циклический сдвиг по двум осям. Так сохраняется период исходной поверхности. Произвольный кроп 512×512 из карты 1K меняет период и может дать шов даже у исходно бесшовного материала. Если проверяем кропы ради мелких деталей, выделить их в отдельный опыт. Повороты направленных текстур допустимы, только если подпись остаётся верной.

## 3. Проверить управляемость до обучения

Реализовать периодические шумы Перлина и Вороного. Для фиксированных параметров проверить воспроизводимость и равенство значений в координатах, сдвинутых на целый период по каждой оси. Подготовить несколько карт с крупным и мелким рисунком. Просмотреть их в раскладке 2×2.

На фиксированных промптах и seed диффузии получить базовый результат SD 1.5 без условия. Затем подать ту же карту через готовые ControlNet для SD 1.5. Для depth использовать нормированную карту высот как приближение глубины, для canny — контуры ячеек. Сравнить на validation две силы воздействия, например 0,5 и 1,0. Проверить, изменяется ли рисунок при смене карты и сохраняется ли тип материала. Контроль — та же генерация с другой картой. Зафиксировать адаптер, предобработку, силу и режим padding до итогового сравнения.

## 4. Обучить предметную LoRA

1. Зафиксировать ревизию SD 1.5, версии библиотек, scheduler, seed, список train-ID и конфигурацию. Заморозить VAE, текстовый энкодер CLIP и исходные веса U-Net. Встроенный CLIP преобразует подпись в последовательность эмбеддингов. Обучаем только LoRA в проекциях внимания U-Net.
2. На каждом шаге VAE кодирует Color в латент. Сэмплировать шаг диффузии и гауссов шум, добавить шум по расписанию SD 1.5. По зашумлённому латенту, номеру шага и эмбеддингам подписи U-Net предсказывает добавленный шум. Для стандартной конфигурации SD 1.5 с epsilon-предсказанием минимизировать среднеквадратичную ошибку между предсказанным и добавленным шумом. Обновлять только параметры адаптера. Процедурная карта формы используется при генерации через ControlNet. Поэтому для этого обучения достаточно реальных пар «подпись — Color», произвольно сопоставлять шум Перлина с фотографией не требуется.
3. Стартовая конфигурация для одной T4: 512², fp16 для вычислений, обучаемые параметры адаптера в fp32, batch 1, накопление градиента 4, gradient checkpointing, AdamW, learning rate 1e-4, rank 16, alpha 16. В журнале считать шагом одно обновление оптимизатора. Контролировать число показанных изображений, чтобы сравнения при разных batch были честными.
4. Пилот на 100 обновлений. Записать loss, секунды на обновление после прогрева, пик VRAM, размер чекпойнта. Проверить сохранение и загрузку LoRA в чистый pipeline, отдельно проверить возобновление с состоянием оптимизатора и номером шага. Рассчитать время полного обучения из замера с запасом на валидацию и сохранения.
5. Начальный ориентир — 1500 обновлений с проверкой каждые 250. На validation отслеживать управляемость, соответствие тексту, стыки и сходство с ближайшими обучающими текстурами. Выбирать чекпойнт по этим результатам. Продление в пределах исходного ориентира 5000 шагов или сравнение рангов 8 и 32 обосновать наблюдаемым недообучением, переобучением и доступной квотой. Записывать все попытки и причины выбора.

### Ноутбук обучения и сохранение состояния

Обучение запускается в Kaggle. В ноутбуке последовательно показать примеры входных пар, число обучаемых параметров, график loss по обновлениям оптимизатора и генерации для фиксированных validation-промптов и seed. Для каждой сетки указать шаг и использованный адаптер.

Каждому запуску выделить каталог в `/kaggle/working/runs/<run_id>/`. До завершения сессии сохранить его в выводе версии Kaggle и проверить доступность файлов из новой сессии.

| Артефакт | Что сохранить |
|---|---|
| `config.json` | Ревизию базовой модели, хеш манифеста данных, версии библиотек, seed, разрешение, аугментации, целевые слои LoRA, rank, alpha, dropout, precision, optimizer, learning rate, scheduler, batch и накопление градиента |
| `metrics.csv` | Шаг, loss, фактический learning rate, время и пиковую VRAM |
| `checkpoints/step-*/` | Веса адаптера, состояние оптимизатора и scheduler, состояние генераторов случайных чисел, позицию в данных, глобальный шаг и состояние scaler при его использовании |
| `adapter/` | Выбранные по validation веса LoRA в safetensors, конфигурацию адаптера и номер соответствующего шага |
| `validation/` | Промпты, seed, параметры инференса и изображения для сравнения шагов |

Контрольные точки записывать по завершении обновления оптимизатора, в конце пилота и полного запуска. Интервал сохранения для полного обучения выбрать после замера времени и размера контрольной точки в пилоте. В Git включить выполненный ноутбук, конфигурацию и ссылку на версию Kaggle с весами и контрольными точками.

## 5. Провести парное сравнение на отложенных данных

| Режим | LoRA | ControlNet | Что измеряем |
|---|---|---|---|
| A | выкл. | выкл. | Исходная генерация по тексту |
| B | выкл. | вкл. | Вклад управления формой относительно A |
| C | вкл. | выкл. | Вклад LoRA при генерации по тексту относительно A |
| D | вкл. | вкл. | Основной результат. Сравнение с B показывает эффект LoRA при управлении формой |

До просмотра test зафиксировать набор описаний из отложенных материалов, две карты формы и не менее трёх seed диффузии на описание при достаточном бюджете. Внутри пары одинаковы промпт, начальный латент, scheduler, число шагов, guidance, разрешение и обработка границ. Режимы без ControlNet вычислять один раз на промпт и seed и переиспользовать при сравнении карт. На test запускать выбранную конфигурацию после завершения подбора.

- **Описание.** Оценить соответствие текста изображению фиксированной версией CLIP и вручную вслепую оценить вид материала, перспективу и запечённые тени. CLIP score служит дополнительным показателем.
- **Структура.** Для карт с выраженными границами сравнивать покрытие их контуров сильными градиентами на сглаженной цветовой карте в пределах фиксированного допуска. Ввести контроль со сдвинутой картой и фиксировать плотность обнаруженных границ, чтобы мелкий шум не выглядел как точное следование форме. Для плавных карт отдельно оценивать крупномасштабное соответствие визуально.
- **Шов.** По каждой оси делить среднюю абсолютную разность яркости через стык на среднюю разность соседей внутри плитки. Для почти однотонных карт отдельно указывать абсолютный перепад. Сопоставлять с настоящими плитками ambientCG и визуальной проверкой 2×2: численная близость краёв сама по себе не гарантирует продолжения рисунка.
- **Отчёт.** Сохранить парные разности D−B по описаниям, разброс по seed, результаты по категориям и примеры неудач. Записать время и пиковую память. Собственные выводы ограничить исследованными категориями и режимами.

## 6. Проверить апскейл и расчёт PBR

Сначала измерить шов на albedo 512², затем после Real-ESRGAN с заворачиванием краёв. Для оценки эффекта повторить апскейл тех же входов с обычной обработкой края. Зафиксировать изменение метрики, время и вид повтора 2×2.

Проверить PBR-сервис двумя способами. На отложенных реальных материалах подать известные Color и доступную карту высот, зафиксировать пресет и сравнить восстановленные карты с совмещёнными эталонами. Для нормалей привести соглашение оси Y к одному формату и измерить угловую ошибку. Для roughness использовать MAE в одной шкале. Если эталон высот подан на вход, явно указать это условие при оценке нормалей. При дополнительной проверке на MatSynth исключить материалы, совпадающие с ambientCG train.

Для сквозной генерации сохранить карту условия, albedo, height, normal, roughness и AO. У синтезированного рисунка нет единственно верной попиксельной пары из каталога. Проверять диапазоны, направления нормалей, стыки и вид материала на плоскости и сфере в Blender при двух направлениях света.

## 7. Дополнительные исследования и передача результатов

После основного сравнения, если останется вычислительный бюджет, отдельно проверить циклический padding против обычного, быстрый адаптер LCM или TCD против выбранного режима и готовую StableMaterials как внешний ориентир по текстовому запросу. Для неё ограничить сравнение общими возможностями: видом материала, швом и временем. Стоимость каждого дополнительного опыта фиксировать отдельно.

Итог НИР — ноутбук для Kaggle, манифест с разбиением, веса LoRA, конфигурация генерации, три модуля конвейера, примеры и таблицы измерений. Проверка готовности — повторить сквозной пример в чистой сессии по записанным версиям и параметрам. В ВКР переносятся методика, фактические результаты и код для интеграции сервисов.
